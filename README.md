# 115年度績效考核流程回饋問卷 — 建置與使用說明

單一網址、三種身分自動分流、資料統一寫入 Google Sheets。

---

## 一、資料夾結構

```
survey/
├── index.html                     # 首頁（唯一進入網址）
├── css/
│   └── style.css                  # 樣式（企業HR質感、低飽和、RWD）
├── js/
│   ├── questions-data.js          # ★ 題目資料（改題目只改這個檔案）
│   ├── config.js                  # 部署設定（Apps Script 網址、標題文字）
│   └── app.js                     # 系統邏輯（分頁、驗證、進度條、送出）
├── google-apps-script/
│   └── Code.gs                    # Google Apps Script 後端（寫入 Sheets）
└── README.md                      # 本說明文件
```

**流程**：首頁選擇身分 →（依身分載入對應題目）→ 分頁填寫 → 驗證必填 → 送出 → 寫入 Google Sheets → 感謝頁。

## 二、Google Sheets 串接設定（第一次部署必做）

### Step 1｜建立試算表

1. 到 Google Sheets 建立一份新的空白試算表，命名例如「115年度績效考核流程回饋問卷_回覆」。
2. 不需要手動建欄位，Apps Script 會在第一次收到資料時自動建立「問卷回覆」工作表與標題列。

### Step 2｜建立 Apps Script

1. 在該試算表點選「擴充功能」→「Apps Script」。
2. 把預設的 `Code.gs` 內容全部刪除，貼上本專案 `google-apps-script/Code.gs` 的完整內容。
3. 按上方儲存（磁片圖示）。

### Step 3｜部署為 Web App

1. 右上角「部署」→「新增部署作業」。
2. 類型選擇「網頁應用程式」。
3. 設定：
   - 說明：可填「績效問卷後端 v1」
   - 執行身分：**我**
   - 存取權限：**知道連結的任何人**（同仁不需要登入 Google 帳號即可填寫）
4. 按「部署」，第一次會要求授權，依畫面指示允許權限。
5. 部署完成後會取得一組網址，格式類似：
   ```
   https://script.google.com/macros/s/AKfycb.../exec
   ```
   請複製這組網址。

### Step 4｜設定前端

打開 `js/config.js`，把網址貼到這裡：

```js
const CONFIG = {
  GAS_WEB_APP_URL: '貼上你的網址',
  ...
};
```

存檔即完成串接。之後每次修改 `Code.gs` 內容，記得回到「部署」→「管理部署作業」→ 選現有部署 → 版本選「新版本」→ 部署，網址才會套用最新程式碼。

### 健康檢查

部署後直接用瀏覽器打開該網址，若看到：
```json
{"result":"ok","message":"問卷後端運作中"}
```
代表後端正常運作。也可以在 Apps Script 編輯器手動執行 `testWriteSample()` 函式，確認能正常寫入試算表。

## 三、如何架設網頁（前端）

這是純靜態網頁（HTML/CSS/JS），沒有伺服器端相依性，任何一種靜態網頁託管方式都可以，例如：

- **GitHub Pages**（您先前的專案也是用這個方式部署，做法相同）：把整個 `survey/` 資料夾內容 push 到一個 repo，開啟 GitHub Pages 指向該分支即可。
- **Google 協作平台 / 內部網頁空間**：直接上傳整個資料夾。
- 本機測試：用任何簡易伺服器開啟 `index.html`（不建議直接用瀏覽器打開 `file://`，因為部分瀏覽器會擋掉本機檔案的 fetch 請求）。例如在資料夾內執行：
  ```
  npx serve .
  ```
  或使用 VS Code 的 Live Server 擴充功能。

部署好網址後，把同一個網址分享給全體同仁、主管、一階主管即可，**不需要建立三個不同網址**——身分選擇後系統會自動切換題目。

## 四、日後修改題目的方式

只需要編輯 `js/questions-data.js`：

- 修改題目文字 → 改對應題目物件的 `label`
- 修改選項 → 改對應的 `options` 陣列
- 修改是否必填 → 改 `required: true / false`
- 新增/刪除題目 → 在對應 `section.questions` 陣列增減物件

**不需要**改動 `app.js`（UI 邏輯會自動套用），也不需要改動 HTML／CSS。

> 若新增了全新的欄位（`field` 名稱是全新的），記得同步到 `google-apps-script/Code.gs` 的 `HEADERS` 與 `FIELD_MAP` 補上對應中文欄位名稱，否則該欄位資料仍會完整保留在試算表最後一欄「其他未定義欄位(JSON)」，不會遺失，但建議補上以利分析。

## 五、資料結構說明（Google Sheets）

三種身分的回覆會寫入**同一份試算表、同一張工作表**（「問卷回覆」），並使用**統一的欄位命名**：

- 相同題目文字（例如「時間安排是否合理」）在三份問卷中共用同一組欄位，方便直接跨身分比較。
- 每份問卷特有的題目（例如僅主管/一階主管填答的「評分困難點」），在其他身分的資料列會自動留空。
- 量表題（例如「非常合理／大致合理／有些趕／明顯不合理」）會同時保留：
  - `_文字` 欄：原始選項文字（供閱讀）
  - `_分數` 欄：對應數值（最佳=最高分），方便直接用公式算平均分
- 複選題會以「；」分隔存成一個儲存格；勾選「其他」時另有獨立欄位存放說明文字。
- 每筆資料都有「填答時間」「身分類別」「所屬單位」，供交叉分析。

## 六、後續分析建議

建議在同一份試算表中，另外新增分析用工作表，使用 `QUERY` 或 Pivot Table 讀取「問卷回覆」工作表的資料，**不要直接在原始回覆工作表上手動修改**，以保留原始資料完整性。

### 常用分析範例（QUERY 公式）

**各身分別填答數**
```
=QUERY(問卷回覆!A:E, "select B, count(A) where A is not null group by B label count(A) '填答數'")
```

**「時間安排合理度」平均分（依身分別）**
```
=QUERY(問卷回覆!A:Z, "select B, avg(F) where F is not null group by B label avg(F) '平均分'")
```
（請依實際欄位字母對照 HEADERS 順序調整欄位代號）

**各部門平均分**
```
=QUERY(問卷回覆!A:Z, "select E, avg(F) group by E label avg(F) '平均分'")
```

### 建議的分析拆分方式

1. **三種身分分開分析**：用「身分類別」欄位篩選/分組，避免員工與主管視角混在一起解讀。
2. **各題平均分／各構面平均分**：利用 `_分數` 欄位做平均，構面可自行分組（例如「流程與時程」= 時間安排合理度 + 溝通清楚度平均）。
3. **整體滿意度**：可將「整體制度比較_分數」與各構面平均分綜合檢視。
4. **部門差異／管理層級差異**：以「所屬單位」「身分類別」「角色說明」交叉分組。
5. **開放式回饋整理**：「做得最好的一件事」「最希望改善的一件事」「其他想法或建議」等開放題建議另存一份文字整理表，用人工或 AI 輔助分類主題（例如：流程時程類、評分標準類、系統操作類），避免逐字曝光在主報告中。

### 匿名性與個資保護原則

- 問卷**未蒐集姓名**，僅蒐集「身分類別」與「所屬單位」，已降低可識別性。
- 若某部門或某身分類別的填答人數過少（建議 **未達 5 人** 時），**不要**在報告中呈現該群組的個別平均分或排名，避免變相識別特定個人的回覆，可改為併入更大的群組（例如跨部門合併、或僅標示「樣本數不足，不呈現」）。
- 開放式文字回饋若內容具高度可識別性（例如提及特定人名、特定事件），建議在對外呈現前先做去識別化改寫。
- 建議將原始回覆工作表的存取權限限縮在 HR 專案負責人，分析後的彙整結果再視需要分享給更大範圍的閱讀對象。

## 七、驗證與必填規則

- **全部題目皆為必填**（單選、複選、量表題、開放式文字題），未作答會在該題下方顯示紅字提示，並自動捲動到第一個未完成的題目。
- 開放式文字題（開放題）欄位提示「請輸入您的想法；若無，請填寫「無」」，填答者若沒有意見，需輸入「無」才能繼續下一步（不可留空）。
- 複選題若勾選「其他」但未填寫說明文字，會被視為未完成，需補上說明才能繼續。
- 進度條與頁碼（第 X／Y 頁）即時反映目前所在的頁面。
- 主管版問卷中，若填答者在「您在本次考核中的角色」選擇「直屬主管（僅進行評分）」，系統會自動跳過「您對部屬的面談（面談者角度）」整個段落，不會出現空白或不相關的題目。

## 八、常見問題

**Q：三份問卷可以個別調整順序或視覺樣式嗎？**
可以，樣式共用同一份 `style.css`，若需要針對特定身分做視覺差異，可在 `app.js` 的 `renderSurvey()` 依 `state.identity` 加上額外的 class name 再於 CSS 中處理。

**Q：填答中途關閉分頁，資料會不會遺失？**
目前為單頁應用、資料僅存在瀏覽器記憶體中，尚未送出前關閉分頁資料會遺失（尚未支援草稿暫存）。若需要「自動儲存草稿」功能，可另行加購此功能，會使用瀏覽器端暫存 + 到職欄位比對的方式實作。

**Q：可以匯出成 Google Form 嗎？**
本系統刻意不採用 Google Form，因為 Google Form 較難做到「同一網址、依身分自動切換完全不同的題目與跳題邏輯」，且較難維持三份問卷共用欄位結構的資料整齊度。目前的網頁 + Apps Script 架構可完整達成您原始需求的跳題邏輯與統一欄位命名。
